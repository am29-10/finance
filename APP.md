# Приложение для телефона

Одна и та же кодовая база даёт четыре способа держать «Кошелёк» под рукой: сайт
на GitHub Pages, иконку с домашнего экрана, устанавливаемый APK для Android и
файл `.ipa` для iPhone. Разница только в том, как файлы попадают на телефон и
где после этого живут данные.

| | Где данные | Что их стирает |
|---|---|---|
| Сайт во вкладке браузера | Хранилище браузера | Очистка данных сайтов |
| Иконка на домашнем экране | Отдельный контейнер иконки | Удаление иконки с экрана |
| APK на Android | Приватная папка приложения | Только удаление приложения |
| IPA на iPhone | Приватная папка приложения | Только удаление приложения |

Резервная копия в Профиле переносит данные между всеми четырьмя: это один файл
JSON, который импортируется обратно кнопкой «Восстановить из копии». Сами по себе
данные между способами не переезжают — это разные хранилища.

## Сборка

Вкладка Actions → **Приложение** → Run workflow. Через несколько минут в разделе
Releases появляется релиз с двумя файлами: `koshelek.apk` и `koshelek.ipa`.
Кнопки в приложении (Профиль → Установить на телефон) ведут прямо на них, минуя
страницу GitHub.

Ни Android SDK, ни Xcode на своём компьютере не нужны: сборка идёт на машинах
GitHub, а для публичного репозитория они бесплатны — включая macOS, которую
иначе пришлось бы покупать целиком ради одной команды.

Номер версии складывается из версии в `package.json` и номера сборки. Обе
платформы берут его из одного места, чтобы не разъехаться внутри одного релиза.

## Android

### Разовая настройка

1. Создайте ключ подписи:

   ```
   npm run keystore
   ```

   Появятся два файла: `wallet-release.jks` и `keystore-secrets.txt`. Оба в
   `.gitignore` и в репозиторий не попадут. **Сохраните их копию отдельно** —
   почему, объяснено ниже.

2. Перенесите четыре значения из `keystore-secrets.txt` в настройки репозитория:
   Settings → Secrets and variables → Actions → New repository secret.

   `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.

### Почему ключ нельзя терять

Android отличает приложения по подписи, а не по названию. Пока APK подписан тем
же ключом, новая версия ставится поверх старой как обновление, и данные
сохраняются. Собранное другим ключом приложение система считает чужим: установка
завершится ошибкой «Приложение не установлено», и единственным выходом будет
удалить старую версию вместе со всей историей операций. Поэтому `versionCode`
берётся из номера сборки напрямую — Android разрешает установку поверх, только
если это число выросло.

Если секреты не заданы, сборка всё равно пройдёт, но выдаст отладочный APK. Он
устанавливается и работает, однако подписан одноразовым ключом: следующая сборка
поверх него уже не встанет. Такой файл к релизу не прикладывается — его можно
скачать артефактом сборки, чтобы посмотреть результат, и нельзя никому раздать.

## iPhone

Здесь тот же принцип, но подпись ставится не на сборке, а на самом телефоне.

iPhone запускает только подписанные приложения, а подпись продаёт Apple: 99 $ в
год за аккаунт разработчика. Бесплатная альтернатива — [SideStore](https://sidestore.io):
он берёт неподписанный `.ipa` и подписывает его обычным Apple ID прямо на
устройстве. Поэтому сборка намеренно не подписывает файл (`CODE_SIGNING_ALLOWED=NO`)
и не экспортирует архив через Xcode — `.ipa` собирается вручную из папки
`Payload`, потому что штатный экспорт требует сертификата, которого нет.

Что это значит на практике:

- Первая установка SideStore требует компьютера и кабеля — один раз. Windows
  подходит, Mac не нужен. Дальше телефон обходится сам.
- Бесплатная подпись действует 7 дней. SideStore продлевает её в фоне, пока
  телефон в Wi-Fi. Пропущенная неделя не стирает данные — приложение просто не
  открывается, пока подпись не обновится.
- Больше трёх таких приложений на один Apple ID держать нельзя.
- Нужен iOS 15 или новее: столько же требует и сам Capacitor (`platform :ios, '15.0'`
  в Podfile).

Инструкция для человека встроена в приложение: Профиль → Установить на телефон →
iPhone → Файлом.

Если однажды появится аккаунт Apple Developer, менять в коде ничего не придётся:
достаточно подписать тот же архив и раздавать через TestFlight по ссылке — до
10 000 человек, без семидневного срока и лимита в три приложения.

### Способ без файла

Тем, кому возня с SideStore не нужна, остаётся короткий путь: добавить сайт на
домашний экран из Safari. Получается та же иконка и тот же полный экран без
адресной строки, ставится в три касания и без компьютера. Плата за простоту —
хранилище: оно принадлежит иконке, и вместе со смахнутой иконкой исчезает вся
история операций.

## Локальная сборка

Нужна, только если хочется собрать файл у себя. Для Android потребуется Android
SDK около 10 ГБ, для iPhone — Mac с Xcode.

```
npm run build:app          # веб-часть в dist-app

npx cap add android        # проект Android из шаблона
npx cap sync android
node scripts/android-icons.mjs
cd android && ./gradlew assembleDebug

npx cap add ios            # проект iOS из шаблона, только на macOS
npx cap sync ios
node scripts/ios-icons.mjs
```

Папки `android/` и `ios/` каждый раз создаются заново и в репозитории не
хранятся: единственный источник настроек — `capacitor.config.ts`. Поэтому
фирменные иконки не лежат в проекте, а рисуются скриптами при каждой сборке —
иначе в приложении оказался бы логотип Capacitor из шаблона.
