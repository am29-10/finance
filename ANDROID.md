# Приложение для телефона

Одна и та же кодовая база даёт три вещи: сайт на GitHub Pages, устанавливаемый
APK для Android и иконку на домашнем экране iPhone. Разница только в том, как
файлы попадают на телефон и где после этого живут данные.

| | Где данные | Что их стирает |
|---|---|---|
| Сайт во вкладке браузера | Хранилище браузера | Очистка данных сайтов |
| Иконка на iPhone | Отдельный контейнер иконки | Удаление иконки с экрана |
| APK на Android | Приватная папка приложения | Только удаление приложения |

Резервная копия в Профиле переносит данные между всеми тремя: это один файл
JSON, который импортируется обратно кнопкой «Восстановить из копии». Автоматически
данные между веб-версией и APK не переезжают — это разные хранилища.

## Сборка APK

APK собирается в облаке GitHub, Android SDK на своём компьютере не нужен.
Готовый файл появляется в разделе Releases репозитория, и прямую ссылку на него
можно отправить кому угодно.

### Разовая настройка

1. Создайте ключ подписи:

   ```
   npm run keystore
   ```

   Появятся два файла: `wallet-release.jks` и `keystore-secrets.txt`. Оба в
   `.gitignore` и в репозиторий не попадут. **Сохраните их копию отдельно** —
   как именно, объяснено ниже.

2. Перенесите четыре значения из `keystore-secrets.txt` в настройки репозитория:
   Settings → Secrets and variables → Actions → New repository secret.

   `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.

### Каждая новая версия

Вкладка Actions → Android APK → Run workflow. Через несколько минут в Releases
появится свежий `koshelek.apk`.

Номер версии складывается из версии в `package.json` и номера сборки, а
`versionCode` берётся из номера сборки напрямую — Android разрешает установку
поверх, только если это число выросло.

### Почему ключ нельзя терять

Android отличает приложения по подписи, а не по названию. Пока APK подписан тем
же ключом, новая версия ставится поверх старой как обновление, и данные
сохраняются. Собранное другим ключом приложение система считает чужим: установка
завершится ошибкой «Приложение не установлено», и единственным выходом будет
удалить старую версию вместе со всей историей операций.

Если секреты не заданы, сборка всё равно пройдёт, но выдаст отладочный APK. Он
устанавливается и работает, однако подписан одноразовым ключом — следующая
сборка поверх него уже не встанет. Это годится, чтобы посмотреть результат, и не
годится, чтобы кому-то раздать.

## iPhone

Установочного файла для iPhone не существует: Apple разрешает ставить приложения
только через App Store, и обойти это без платного аккаунта разработчика (99 $ в
год) и компьютера Mac нельзя.

Рабочая замена — добавить сайт на домашний экран из Safari. Получается та же
иконка и тот же полный экран без адресной строки; отличается только способ
установки. Инструкция встроена в приложение: Профиль → Установить на телефон.

Если однажды понадобится именно установка файлом, порядок такой: аккаунт Apple
Developer, `npm i @capacitor/ios`, `npx cap add ios`, сборка в Xcode на Mac и
раздача через TestFlight по ссылке (до 10 000 человек). Код приложения при этом
не меняется — Capacitor уже настроен.

## Локальная сборка

Нужна, только если хочется собрать APK у себя. Потребуется Android SDK около
10 ГБ.

```
npm run build:app          # веб-часть в dist-app
npx cap add android        # проект Android из шаблона
npx cap sync android
node scripts/android-icons.mjs
cd android && ./gradlew assembleDebug
```

Папка `android/` каждый раз создаётся заново и в репозитории не хранится:
единственный источник настроек — `capacitor.config.ts`.
